# My Study Diary

## What is this project?

**My Study Diary** is a web application created to motivate people who are studying, especially people who are learning computer science or programming.

The application allows you to save your study sessions and see your progress.

It includes a study streak, the number of days studied this month, your best streak, goals, a history of your study sessions and a GitHub-style study heatmap.

---

# Features

## Study Streak

The application shows:

* **Current Streak** – How many days in a row you have studied.
* **Days This Month** – How many days you have studied during the current month.
* **Best Streak** – Your longest study streak.

## Study Sessions

You can create a new study session with:

* Date
* Topic
* Minutes studied
* Notes about what you learned

## Session History

All your saved study sessions are displayed in the application so you can see what you have studied.

## Goals

You can create a study goal and track your progress.

The application includes a two-week goal system to help you stay motivated.

## Study Heatmap

The application includes a GitHub-style heatmap that shows your study activity.

The more you study, the more activity you can see on the heatmap.

---

# How to use it

1. Download the following files:

   * `index.html`
   * `style.css`
   * `app.js`

2. Put all three files in the same folder.

3. Open `index.html` in your browser.

The application works directly in the browser and does not require a server or installation.

# How was it created?

## 1. Defining the idea

First, I defined the idea of creating a study diary for people who want to track their study progress.

## 2. Using OpenCode

I used **OpenCode** as an AI coding agent to help develop the project.

The agent could analyze the project, create and modify files, implement features and help find problems.

## 3. Prompt Engineering

I used structured prompts to communicate with the AI agent.

The prompts were based on:

* Role
* Context
* Task
* Constraints / Rules
* Output format

This made the instructions clearer and helped the agent understand what needed to be done.

## 4. `AGENTS.md`

I created an `AGENTS.md` file to give the AI agents permanent instructions about the project.

It contains information such as:

* Project rules
* Technologies used
* How the project should work
* Coding rules
* Important decisions

This means that when I start a new OpenCode session, the agent can understand the project more easily.

## 5. `MEMORY.md`

I also created a `MEMORY.md` file.

This file contains the memory of the project, such as:

* Important decisions
* Implemented features
* Changes
* Known problems
* Limitations
* Next steps

This helps the AI agent continue working on the project between different sessions.

## 6. Plan Mode

Before implementing some features, I used **Plan Mode**.

Instead of immediately writing code, the agent first analyzed the request and created a plan.

The plan included:

* Which files would be modified
* How the feature would work
* Possible edge cases
* Important decisions
* Changes that would be needed

I could then review the plan before allowing the agent to modify the code.

## 7. Spec-Driven Development

The project also followed the idea of **Spec-Driven Development (SDD)**.

The general process was:

**Constitution → Specification → Clarification → Plan → Tasks → Implementation → Validation**

This helped organize the development process before writing the code.

## 8. Additional features

During the development of the project, additional features were added, such as the study heatmap.

These features were planned and then implemented using the AI agent.

## 9. Testing with Chrome DevTools

After implementing features, I used **Chrome DevTools** to test the application.

This helped me find problems and check if the application worked correctly.

## 10. Agents and Subagents

The project also uses the idea of multiple agents and subagents.

A possible workflow is:

**Coordinator → Planner → Implementer → Reviewer**

Each agent can have a different responsibility during development.

## 11. Development methodology

The general methodology used for this project was:

**Idea → Prompt → AI Agent → AGENTS.md → MEMORY.md → Planning → Specification → Implementation → Testing → Review → Improvement**

This was the process I followed to develop the project using AI.

## 12. What I learned

During this project, I learned that AI can help with a lot of the technical work, but the human still needs to define:

* What the project should do
* The rules and limitations
* What the AI should change
* Whether the proposed plan is correct
* Whether the final result works correctly

The AI helps with the development, but the human is responsible for directing and validating the project.
